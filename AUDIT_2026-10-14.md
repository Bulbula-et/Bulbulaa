# Bulbula.et V1 — End-to-End Architecture, Security & Open-Source Adoption Audit

**Audit date:** 2026-10-14  
**Scope:** Current repository through customer/staff authentication, discovery, moderation, sponsorship, analytics, cache, SQLite/MySQL schema, and shared-hosting deployment.  
**Method:** Source review, dependency audit, PHP lint, PHPStan, PHPUnit, live HTTP route verification, authenticated staff login/RBAC flow, customer OTP flow, CSRF negative test, database integrity checks, and deployment/config review.

## Executive result

The application is a functional V1 prototype with a coherent plain-PHP structure, prepared SQL, output escaping, HMAC-hashed OTPs, CSRF checks on reviewed mutation endpoints, separated staff/customer sessions, and newly library-backed SMTP and Google identity verification. It is **not yet production-ready**. The highest risks are configuration defaults that expose the Staff Console in preview mode, seeded/shared staff credentials, claimed-but-unenforced staff TOTP, plaintext secrets in a UI-writable tracked JSON file, and a media feature that records arbitrary paths rather than securely processing uploads.

The audit found and fixed one concrete integration regression: the Google verifier dependency and PHPMailer import had been partially disconnected by overlapping edits. PHPStan and new authenticated E2E coverage now detect this class of failure.

## Findings by severity

### CRITICAL — Must resolve before any public production deployment

1. **Staff preview bypass is enabled by default.** `security.require_staff_login` is false, and `StaffAuthService` defaults unauthenticated staff traffic to Administrator #1. The router also permits preview role switching. Production must fail closed, remove auto-login, and make preview behavior impossible when `app.env=production`.
2. **Seeded/shared staff password behavior remains.** The known pilot password and automatic fallback upgrade path are useful only for local demos. Production deployment must create a unique first Administrator through a one-time CLI/bootstrap command and remove/disable all seeded staff accounts.
3. **D-45 TOTP gap was remediated after this audit.** Staff password login now proceeds to RFC 6238 enrollment/verification using the standalone zero-dependency `robthree/twofactorauth` library. Secrets are encrypted at rest with native libsodium secretbox, challenges expire, attempts are limited, actions are audited, and another Administrator can reset a lost enrollment.
4. **Secret storage is not production-safe.** SMTP, Google, Telegram, database and application secrets can be stored in plaintext `config/env.json`, which is tracked and writable through `/staff/settings`. Even outside `public_html`, backup leakage, source upload mistakes, and malicious administrator/session compromise increase impact.
5. **Media upload gap was remediated after this audit with native shared-hosting PHP.** The endpoint now accepts real multipart uploads, checks PHP upload integrity and actual Fileinfo byte MIME, bounds bytes/dimensions/pixels, decodes with GD, resizes, re-encodes to JPEG to strip metadata/polyglot payloads, generates random server filenames, stores measured metadata, cleans up on DB failure, and blocks script execution in the media directory.

### HIGH — Resolve before production acceptance

6. **Rate-limiter race was remediated after this audit without a framework dependency.** The limiter now uses one hashed bucket file per policy key, exclusive OS `flock`, locked read/prune/append/truncate/write, `fflush`, restrictive permissions, and fail-closed I/O behavior. CI executes 24 concurrent PHP processes and requires exactly 5 allows / 19 denials for a five-attempt policy.
7. **Custom session and CSRF stack lacks complete hardened lifecycle controls.** Cookie `secure` is not explicitly set, idle timeout is not enforced server-side, CSRF tokens are not rotated after privilege changes, and the custom layer has less review than established components.
8. **Application configuration updates are not atomic/validated enough.** Settings write directly to the live JSON path, do not use temp-file + atomic rename, and do not validate all host/client-ID formats before replacing configuration.
9. **No real external-provider integration test is possible without CI secrets.** Google signed-token success and actual SMTP delivery require staging credentials. Current CI correctly tests safe rejection/adapters and the OTP application flow, but not third-party delivery success.
10. **Staff authorization is partly distributed in controllers.** The central router checks authentication, while role authorization is repeated per action. A missed check can expose a future administrator operation.
11. **Logout CSRF inconsistency was found and fixed during this audit.** Both customer and staff POST logout endpoints now verify CSRF.
12. **Development debug/preview data is committed.** `app.debug=true`, SQLite pilot data, preview OTP visibility, and known staff identities must be impossible in production configuration.

### MEDIUM

13. Custom router/request/response code is small but protocol-sensitive and lacks PSR-7/PSR-15 interoperability.
14. Custom cache/tag invalidation and live OPcache refresh logic needs concurrency/failure testing on LiteSpeed/cPanel.
15. Validation is distributed across controllers, increasing drift and inconsistent error handling.
16. **Database migration gap was remediated after this audit without a framework dependency.** A plain-PHP MySQL/SQLite runner now provides timestamp ordering, SHA-256 immutability checks, batches, status, idempotent apply, last-batch rollback, transactions where supported, and a shared-hosting deployment lock.
17. **Structured production logging was remediated after this audit.** Monolog is now a pinned direct dependency behind `Core\\Logger`, with JSON records, request correlation IDs, recursive secret redaction, safe exception metadata, fourteen-day file rotation, restrictive permissions, and centralized safe HTTP error handling.
18. Security headers lack a Content-Security-Policy, Permissions-Policy, and explicit frame policy/frame-ancestors strategy appropriate for Web and Telegram.
19. E2E currently focuses on success flows and one CSRF negative path; mutation workflows need database-state assertions and authorization-negative cases.
20. SQLite/MySQL parity is not automatically tested against a real MySQL/MariaDB service.

## Mature open-source adoption plan

The rule is **focused components, not a heavy framework**, preserving the plain-PHP/shared-hosting constraint.

| Current custom area | Recommended mature package/project | Priority | Decision |
|---|---|---:|---|
| SMTP/MIME | `phpmailer/phpmailer` | Done | Integrated and pinned |
| Google ID token verification | `google/apiclient` | Done | Integrated and pinned |
| Testing | `phpunit/phpunit` | Done | Integrated as dev dependency |
| Static analysis | `phpstan/phpstan` | Done | Integrated as dev dependency |
| Routing | `nikic/fast-route` | High | Replace regex router before route count grows further |
| HTTP request/response/session | `symfony/http-foundation` | High | Adopt incrementally; provides hardened cookies/session bags and HTTP semantics |
| CSRF | `symfony/security-csrf` | High | Replace custom token helper after HttpFoundation session adapter |
| Rate limiting | Atomic plain-PHP `flock` implementation | Done | Framework package skipped; concurrency behavior is now directly tested in CI |
| Cache | Existing file cache, with targeted hardening/tests | Medium | Symfony component skipped to preserve the plain-PHP/shared-hosting constraint |
| Secret loading | `vlucas/phpdotenv` plus host environment variables | Critical | Secrets outside tracked JSON; UI shows status, not secret values |
| TOTP | `robthree/twofactorauth` or another actively maintained RFC 6238 package after final review | Critical | Implement enrollment, encrypted secret storage, recovery codes and login challenge |
| Image decoding/resizing | Native PHP GD | Done | Framework/library skipped; decode/re-encode pipeline is small and shared-hosting native |
| MIME identification | Native PHP Fileinfo | Done | Actual byte MIME validation; extension and browser MIME are ignored |
| File storage abstraction | Plain local storage with random names | Done for V1 | Flysystem skipped; reconsider only if object storage becomes a real requirement |
| Logging | `monolog/monolog` | High | Structured rotating logs with PII scrubbing |
| Validation | `symfony/validator` | Medium | Central DTO/input constraints and consistent errors |
| Database migrations | Plain-PHP `MigrationRunner` | Done | Phinx skipped to avoid deployment/dependency weight; checksummed runner is covered by PHPUnit and CI |
| Telegram Bot/Mini App APIs | `irazasyed/telegram-bot-sdk` (verify maintenance/security immediately before adoption) | High | Avoid custom API plumbing; initData validation still needs specification-conformant tests |
| HTML sanitization if rich text is introduced | `ezyang/htmlpurifier` | Conditional | Not needed for current escaped plain text; adopt before allowing HTML |

## Areas that should remain domain-owned custom logic

Using a library everywhere is not automatically safer. Keep these small, tested, application-specific rules:

- Branch/business separation and permission/QC publication gates.
- Review 30-day policy, one-review rule, and unweighted rating calculation.
- Opening-hours domain statuses and Addis Ababa display semantics (but use trusted date/time primitives).
- Sponsorship/organic separation and readiness gates.
- Branch/area/category repositories and SQL optimized for the defined catalogue.
- Audit event vocabulary and governance workflow.

## Recommended implementation order

1. Remove preview/admin bypass in production, remove seeded credential fallback, and add a one-time admin bootstrap command.
2. Move secrets to environment variables using `vlucas/phpdotenv`; make `/staff/settings` status-only for secrets.
3. Implement real TOTP with a mature RFC 6238 library and recovery workflow.
4. Replace rate limiting/cache with Symfony components.
5. Implement secure media uploads with Symfony Mime + Intervention Image + Flysystem.
6. Add Phinx migrations and CI MySQL/MariaDB parity testing.
7. Migrate routing/HTTP/session/CSRF to FastRoute and focused Symfony components.
8. Add Monolog and security-header policy.
9. Add staging-only SMTP and Google success tests using GitHub encrypted secrets.
10. Expand authorization-negative and state-mutating E2E tests.

## CI policy now enforced

`.github/workflows/ci.yml` runs on pushes and pull requests to `main` and manually. It validates and audits Composer, installs locked dependencies, lints PHP, runs PHPStan and PHPUnit, rebuilds SQLite, starts the app, verifies routes/data/cache/404, and executes authenticated staff/customer/CSRF flows on PHP 8.2, 8.3 and 8.4. The workflow has read-only repository permissions, a timeout, concurrency cancellation, failure logs, and deterministic dependency installation.
