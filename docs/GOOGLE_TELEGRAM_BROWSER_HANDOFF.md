# Google sign-in from the Telegram Mini App

**Problem:** The existing Google Identity Services popup was rendered inside Telegram's embedded Mini App. Google says GIS sign-in is not available in WebViews. On Android and Desktop, the user observed a blank `accounts.google.com/gsi/transform` page after selecting an account; the ordinary browser sign-in works. A browser window does not automatically share the Mini App's application session, so merely opening Google externally does not sign the Mini App in.

**Supported handoff:** Inside Telegram, the login page offers **Continue with Google in a browser** instead of rendering the Google GIS widget in the embedded WebView. It creates a five-minute, one-time challenge bound to the original Mini App's PHP session by an independent 256-bit secret stored only server-side. The waiting screen's button uses Telegram's `openLink` directly on a user gesture to open the Bulbula-hosted verification page in a browser. The browser runs the existing official GIS widget and server-side Google ID-token verification. Only after a valid Google identity is confirmed does the originating Mini App session poll and atomically consume the challenge, rotate its session ID, and sign in. The external browser never receives the Mini App session secret; the handoff database stores hashes, a Customer ID, and expiry/consumption timestamps, never an ID token or email.

**User instructions:** Tap Continue with Google, tap **Open Google sign-in in browser**, complete Google in the browser, then switch back to the existing Telegram Mini App. The Mini App should finish sign-in automatically within five minutes. Browser security prevents silently closing another app or forcing the OS to switch back to Telegram; the browser confirms verification and tells the user to return. A canceled, expired, or previously consumed link requires a fresh start. If Google fails even in a normal browser, check the authorized JavaScript origin for the configured Google Web client and browser popup/cookie settings; do not spoof user agents, weaken TLS, or bypass Google policy.

**Verification:** CI tests forged-ID-token rejection, a second session's inability to consume the verified flow, one-time consumption, and a synthetic fixture's Mini App account session on both SQLite and MariaDB. CI does not use a real Google account or a physical Telegram client. The user must retry on Telegram Android and Desktop (and iOS where available) before this launch issue is marked resolved. Do not paste Google credentials, browser challenge links, session cookies, or Telegram launch data into logs or tickets.

References: [Google GIS integration: WebViews are unsupported](https://developers.google.com/identity/gsi/web/guides/integrate), [Google embedded WebView OAuth policy](https://developers.googleblog.com/upcoming-security-changes-to-googles-oauth-20-authorization-endpoint-in-embedded-webviews/), [Telegram Mini App external-link event](https://core.telegram.org/api/web-events).
